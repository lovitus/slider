# Release and package publishing

Slider releases are driven by GitHub Actions and GoReleaser. GoReleaser is the only binary/package artifact source; the repository scripts only update package-manager manifests and Linux repository metadata.

## Release tags

Use strict semantic tags:

```bash
git tag v1.2.3
git push origin v1.2.3
```

- `vX.Y.Z` publishes GitHub Release assets, updates `Formula/slider.rb` and the root `slider.json` Scoop manifest on `master`, and publishes APT/RPM repository metadata to `gh-pages`.
- `vX.Y.Z-suffix` publishes GitHub Release assets only.
- Other `v*` tags fail before release work starts.

The default branch for this repository is `master`; package manifests are committed back to `master`. Linux package repositories are published from `gh-pages`.

## Required secrets

Stable releases require these repository secrets:

- `PACKAGE_GPG_PRIVATE_KEY`: ASCII-armored private key for signing APT Release metadata and RPM repository metadata.
- `PACKAGE_GPG_PASSPHRASE`: passphrase for the signing key.

The workflow uses the default `GITHUB_TOKEN` to create releases and push generated package metadata. If branch protection blocks bot pushes to `master` or `gh-pages`, use a dedicated release bot token and update the workflow credentials before cutting a stable release.

## Artifact layout

GoReleaser produces archives with no wrapper directory:

- `slider_VERSION_darwin_amd64.tar.gz` contains `slider` at archive root.
- `slider_VERSION_linux_amd64.tar.gz` contains `slider` at archive root.
- `slider_VERSION_windows_amd64.zip` contains `slider.exe` at archive root.

The same layout is used for `arm64`. Homebrew and Scoop manifests assume these exact internal paths. Scoop reads app manifests from the bucket repository root, so `slider.json` must stay at the top level of this repository.

Linux packages are generated by GoReleaser/nFPM:

- `slider_VERSION-1_amd64.deb`
- `slider_VERSION-1_arm64.deb`
- `slider-VERSION-1.x86_64.rpm`
- `slider-VERSION-1.aarch64.rpm`

APT metadata is signed. RPM repository metadata is signed; individual RPM packages are not signed in this setup, so the published repo file uses `repo_gpgcheck=1` and `gpgcheck=0`.

## Local verification

Before pushing a release tag:

```bash
go build .
./slider --version
GOOS=linux GOARCH=amd64 go test -vet=off ./...
go run github.com/goreleaser/goreleaser/v2@v2.16.0 check
go run github.com/goreleaser/goreleaser/v2@v2.16.0 release --snapshot --clean
```

On Windows, `go test -vet=off ./...` may fail for the Linux-only `service/dhcpd` dependency path. Use the Linux-targeted command above to match the release CI environment.
